4. JACK NETWORK COLOR SYSTEM

The primary visual hierarchy is:

BLACK → SILVER → RED

Black is the foundation.

Silver provides typography, structure, and sophistication.

Red communicates interaction, importance, and brand energy.

- Panels

#080808

49. MOBILE & RESPONSIVE DESIGN — MANDATORY

The mobile experience is a first-class version of the website, not a scaled-down desktop version.

- Design mobile-first, then progressively enhance for tablet and desktop.
- The website must work flawlessly on small phones, standard phones, tablets, laptops, and large desktop displays.
- Test at minimum: 320px, 360px, 375px, 390px, 414px, 768px, 1024px, 1280px, and 1440px+ widths.
- Support portrait and landscape layouts where relevant.
- No horizontal scrolling, clipped content, overlapping elements, broken layouts, or elements extending outside the viewport.
- Never simply shrink the desktop layout. Recompose sections specifically for mobile.
- Navigation must have a proper mobile navigation/menu experience.
- All buttons and interactive elements must have comfortable touch targets.
- Never rely exclusively on hover; every important interaction must work properly on touch devices.
- Typography must resize naturally without awkward wrapping or oversized headings.
- Grids, cards, tables, forms, images, videos, and other content must intelligently reflow on smaller screens.
- Hero sections must be intentionally designed for mobile rather than compressed from desktop.
- Modals, dropdowns, menus, tooltips, notifications, and overlays must remain completely usable within the viewport.
- Forms must be comfortable to use with mobile keyboards.
- Respect mobile safe-area insets where necessary.
- Optimize images, animations, fonts, and assets for mobile performance and bandwidth.
- Avoid excessive animations on lower-powered/mobile devices.
- Maintain the Jack Network visual identity on mobile: black foundation, silver information, red actions.
- Do not remove important functionality simply because the screen is smaller. Adapt the UX instead.
- Ensure sufficient contrast, readable text, visible focus states, and accessible touch interactions.
- Test actual interaction states on mobile, not just the static layout.
- Check scrolling behavior, sticky elements, menus, buttons, forms, animations, and viewport resizing.
- Test both very small screens and large screens to prevent breakpoint-specific bugs.

MOBILE QA IS REQUIRED

Before considering the website finished:

BUILD → RUN → TEST MOBILE → INSPECT → IDENTIFY ISSUES → FIX → TEST AGAIN

Do not declare the website complete if the desktop version looks good but the mobile version has layout, usability, performance, or interaction problems.

Mobile quality must be equal to desktop quality.

50. NON-NEGOTIABLE QUALITY STANDARDS

1. No fake functionality
Never create buttons, forms, dashboards, counters, login systems, server status displays, APIs, or integrations that only look functional. If functionality isn't implemented, either ask me or clearly mark it as unavailable.

2. Real content only
Never invent pricing, player counts, uptime, customers, testimonials, partnerships, statistics, server specifications, or business claims. Ask me when real information is required.

3. Accessibility
Follow WCAG principles. Ensure keyboard navigation, visible focus states, sufficient contrast, semantic HTML, accessible labels, and reduced-motion support.

4. Performance
Keep the site fast. Avoid unnecessary libraries, huge images, excessive JavaScript, unnecessary animations, and oversized dependencies. Optimize images, fonts, code splitting, and loading behavior.

5. Security
Never expose secrets or credentials in client-side code. Use environment variables and server-side validation/authentication. Never trust client-side permissions. Validate user input and protect API/database operations.

6. Error/loading/empty states
Every real dynamic feature must have proper loading, empty, error, retry, and success states where applicable. Never leave users staring at a blank screen.

7. Visual consistency
Establish centralized design tokens for colors, spacing, typography, borders, radii, shadows, animation timing, and breakpoints. Do not randomly invent new values throughout the project.

8. Don't over-animate
Animation should communicate interaction or provide useful feedback. Do not animate everything. Respect prefers-reduced-motion.

9. Cross-browser
Test important functionality on modern Chrome, Firefox, Safari, and Edge, especially responsive layouts and interactive components.

10. Final visual QA
Do not stop after the first successful build.

BUILD → RUN → INSPECT → SCREENSHOT → FIND PROBLEMS → FIX → REPEAT
